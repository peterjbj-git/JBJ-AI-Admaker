# ad-video-maker — 광고 영상 제작 파이프라인

힉스필드 MCP(에셋 생성) + Remotion CLI(합성·렌더링) + 유튜브 벤치마킹을 결합해
완성형 광고 영상을 제작한다. 산출물: 최종 mp4, 스토리보드, 벤치마킹 자료, 제작 보고서.

## 절대 원칙 — 질문은 3회 관문에서만

| 관문 | 시점 | 내용 |
|------|------|------|
| 질문 ① | 1단계 시작 시 | 니즈 일괄 수집 (광고 대상·타깃 시장·포맷·크레딧 상한) |
| 질문 ② | 2단계 벤치마킹 결과 제시 후 | 선호 방향 선택 |
| 질문 ③ | 3단계 스토리보드 제시 후 | 수정 반영 → 최종 확정 |

**질문 ③에서 확정된 스토리보드는 '최종 계약'이다.** 4단계(에셋 생성) 진입 이후에는
어떤 질문도 하지 않는다. 생성 실패·품질 미달·크레딧 부족 등 모든 돌발 상황은
스스로 판단(재생성, 모델 교체, 씬 수 축소)해 해결하고, 판단 내역을 최종 보고서에 기록한다.
이유: 유저는 생성 시작 후 자리를 비울 수 있고, 중간 질문 하나가 파이프라인 전체를 블로킹한다.

## 작업 폴더 규약

프로젝트마다 저장소 루트에 `ad-videos/<프로젝트-슬러그>/` 를 만들고 아래를 저장한다.

```
ad-videos/<slug>/
├── brief.md          # 1단계: 니즈 수집 결과 정리
├── benchmark.md      # 2단계: 벤치마킹 조사 + 선정 근거
├── benchmark/        # 2단계: 다운로드한 벤치마킹 영상 (유저 시청용)
├── storyboard.md     # 3단계: 확정 스토리보드 (씬·프롬프트·크레딧 계획)
├── assets/           # 4단계: 다운로드된 힉스필드 생성물
├── scenes.json       # 5단계: 렌더링에 사용한 구성 파일 사본
├── final/            # 최종 mp4
└── report.md         # 최종 보고서 (자율 판단 내역 포함)
```

## 워크플로우

### 1단계 — 니즈 일괄 수집 (질문 ①)

`references/needs-checklist.md` 를 읽고 그대로 진행한다.
핵심: 광고 대상·메시지, **타깃 지역·인종·문화권·언어**, 비율·길이·플랫폼, 톤앤매너,
**음성 구성(내레이션 / 등장인물 대사 / 자막만)**, **크레딧 사용 상한**, 그리고
**제품 이미지·로고 보유 여부(있으면 파일 경로)**를 이 시점에 전부 받는다.
음성 구성은 4단계 비디오 모델 선정(대사는 음성 지원 모델 필요)과 믹싱에 직결되므로
이 관문 이후에는 변경하지 않는다. 받은 이미지는 `assets/input/` 에 복사해 두고,
결과를 `brief.md` 로 정리한다.

### 2단계 — 지역 맞춤 유튜브 벤치마킹 (질문 ②)

`references/youtube-benchmark.md` 를 읽고 진행한다.
타깃 지역의 언어로 검색 키워드를 구성해 트렌디한 광고 3~5편을 조사하고,
**후보 영상을 `benchmark/` 폴더에 다운로드해 로컬 경로를 안내한다** (유저가 직접 시청 가능).
스타일 분석표 + 다운로드 경로와 함께 방향 후보 2~4개를 제시한 뒤
AskUserQuestion으로 어떤 영상 스타일을 참고할지 선택받는다.
결과와 선정 근거를 `benchmark.md` 로 정리한다.

### 3단계 — 스토리보드 작성·확정 (질문 ③)

brief + 선택된 벤치마킹 방향을 바탕으로 씬별 구성안을 작성한다:
씬 번호·길이·힉스필드 프롬프트(타깃 인종·문화 반영)·자막 카피·오디오 계획·**예상 크레딧**.
**씬은 메시지 단위, 컷은 비주얼 단위다.** 지루함을 막기 위해 씬을 컷으로 쪼개
15초 기준 총 6~8컷(컷당 1.5~2.5초), 30초 기준 10~14컷으로 구성하고,
스토리보드는 **컷 단위**로 작성한다 (컷마다 프롬프트·길이 명시).
자막은 트렌디한 키네틱 스타일이 기본이며, 핵심 단어는 `*단어*` 마크업으로 강조 컬러를 지정한다.
음성 구성이 '등장인물 대사'면 **씬별 대사문**을, '내레이션'이면 **내레이션 대본**을
스토리보드에 포함해 질문 ③에서 문구까지 함께 확정받는다 (4단계에서 문구를 새로 지어내지 않는다).
AskUserQuestion으로 "이대로 진행 / 수정 요청"을 받고, 수정이 있으면 반영해 재확인한다.
확정본을 `storyboard.md` 로 저장한다. 예상 크레딧이 상한을 넘으면 씬 수·생성 횟수를
줄여 상한 안으로 맞춘 안을 제시한다.

### 4단계 — 힉스필드 에셋 생성 (무중단)

`references/higgsfield-prompting.md` 를 읽고 진행한다.
ToolSearch로 힉스필드 도구를 일괄 로드 → `balance` 로 잔여 크레딧 확인 →
`models_explore(recommend)` 로 모델 선정 → 키 비주얼 이미지 → 씬별 비디오 → 오디오 순서로 생성한다.
오디오(BGM·내레이션·SFX)는 `references/audio-guide.md` 의 프롬프트 공식·믹싱 기준을 따른다.
**유저가 제품 이미지를 제공한 경우** `media_upload` 로 힉스필드에 업로드해 참조 입력으로 사용한다
(실물 제품 외형을 보존하는 것이 텍스트 프롬프트 생성보다 항상 우선).
생성물은 `scripts/download-assets.ps1` 로 `assets/` 에 다운로드한다.

### 5단계 — Remotion 합성·렌더링 (무중단)

`references/remotion-pipeline.md` 를 읽고 진행한다.
`templates/remotion-ad/` 는 사전 구성된 렌더링 엔진이다(코드 수정 불필요).
에셋을 템플릿의 `public/assets/` 에 복사하고 `src/scenes.json` 만 작성하면
비율별 Composition(`Ad-16x9`, `Ad-9x16`, `Ad-1x1`)으로 렌더링된다.
최종 mp4를 `final/` 에 저장하고 파일 크기·재생 길이를 검증한다.

## 크레딧 규칙

- 4단계 시작 전 `balance` 확인. 실제 잔액 < 스토리보드 예상치면 **질문 없이** 씬 수·재생성 횟수를 자동 축소하고 보고서에 기록한다.
- 씬당 재생성은 최대 2회. 2회 실패 시 해당 씬을 이미지+켄번즈(scenes.json의 `type: "image"`)로 대체한다.
- 크레딧 상한의 10%는 예비비로 남겨둔다 (마지막 씬 실패 대비).

## 오류 대응 (전부 자율 판단, 질문 금지)

| 상황 | 대응 |
|------|------|
| 힉스필드 생성 실패 | 1회 재시도 → 모델 교체 → 이미지 씬으로 대체 |
| 다운로드 실패 | 스크립트가 3회 재시도. 최종 실패 시 해당 에셋 재생성 |
| 렌더링 실패 | 에러 로그 분석 → scenes.json 수정 → 재렌더. 특정 에셋 문제면 해당 씬 제외 후 렌더 |
| 크레딧 소진 | 남은 씬을 색상/이미지 씬으로 대체하고 보고서에 명시 |

## 최종 보고 형식 (report.md 및 유저 보고)

1. **결과물**: 최종 mp4 경로, 비율, 길이, 파일 크기
2. **벤치마킹 근거**: 참고 영상과 반영 요소
3. **씬별 구성**: 각 씬의 소스(모델)와 내용
4. **크레딧 정산**: 예상 vs 실제 소모량
5. **자율 판단 내역**: 4~5단계에서 스스로 결정한 사항과 이유
